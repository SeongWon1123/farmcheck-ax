# 팜체크 사용 안내

팜체크는 녹차 재배 기록 가운데 다시 볼 기록을 찾아 주고, 원본 근거와 아직 풀리지 않은 질문을 다음 담당자에게 넘기는 도구입니다.
진단, 처방, 원인 확정은 하지 않습니다. 원본 기록도 고치지 않습니다.

> 표기 규칙: **[관측]** 은 이번 작업에서 실제로 확인한 사실, **[계획]** 은 아직 하지 않은 일, **[주입]** 은 시연용으로 일부러 넣은 합성 상황입니다.

## 1. 누가, 언제 쓰나요

- 기록 담당자: 이상해 보이는 값의 원문, 단위, 시각을 확인할 때
- 교대 담당자: 앞사람이 보류한 기록과 남긴 질문을 이어받을 때
- 관리자: 이번 주에 무엇을 확인했고 무엇이 열려 있는지 볼 때

## 2. 화면 구성

| 영역 | 보이는 것 |
| --- | --- |
| 상단 표시줄 | 데이터 모드(공개 시연은 `합성 시연 데이터`), 작업공간 버전, AgentStream 상태 |
| 기록 목록 | 필터: 후보, 전체, 보류, 재검토 필요, 해소됨 |
| 기록 상세 | 원문 값, 해석한 값, 단위 출처, 사진과 환경 시각 차이, 규칙 결과, 같은 환경 묶음, 비교 기록 |
| 작업 패널 | 검토함, 보류, 수정, 재검사, 모델 분류 요청, 해소 처리 |
| 인수인계 | 범위 선택, 스냅샷 생성, JSON/CSV/HTML 내려받기 |

## 3. 한 건을 끝까지 처리하는 순서

1. **후보 열기.** 목록에서 후보 기록을 엽니다. 후보 이유(예: `PH_SCREEN`, pH가 14보다 큼)와 그 규칙이 *결론 내리지 않는 것* 이 함께 보입니다.
2. **원본 확인.** 원문 문자열 그대로의 값과 해석값을 비교합니다. 단위가 캡션에서 온 것이면 `출처 선언` 으로 표시되며, 독립 근거가 아닙니다.
3. **사진 보기.** [관측] 원천 사진은 모두 380x380 픽셀입니다. JSON에 적힌 해상도(1920x1080 등)와 다릅니다. 그래서 확대나 좌표 표시는 하지 않습니다.
4. **같은 환경 묶음 보기.** 같은 측정 시각과 같은 pH, EC, CO2, 온도를 가진 기록끼리 묶어 보여 줍니다. 묶음은 보기용입니다. 합치거나 지우지 않고, 한 기록의 처리가 다른 기록으로 번지지 않습니다.
5. **판단 남기기.** 세 가지 중 하나를 고릅니다.
   - `검토함`: 봤다는 표시입니다. 문제가 풀렸다는 뜻이 아닙니다.
   - `보류`: 이유와 다음 할 일을 반드시 적습니다. 인수인계에 그대로 실립니다.
   - `수정`: 허용된 필드에 새 원문 값과 사유를 적습니다. 원본은 그대로 두고 덧씌우기로 저장됩니다. 이전 검토와 해소는 무효가 됩니다.
6. **재검사.** 수정이나 모델 결과 채택 뒤에는 재검사를 눌러 현재 값으로 규칙을 다시 돌립니다. 재검사는 스스로 해소하지 않습니다.
7. **해소 처리.** 최신 재검사가 있고, 근거 메모와 근거 참조를 적어야 가능합니다. 같은 JSON을 다른 말로 옮긴 것은 새 근거가 아닙니다. 화면에는 `사람이 근거를 기록해 해소 처리` 로 남습니다.
8. **인수인계.** 범위를 고르고 스냅샷을 만듭니다. 열려 있거나 보류된 기록도 넘길 수 있고, 눈에 띄게 미해결로 표시됩니다.

## 4. 두 개의 상태 축

검토 상태(`미검토`, `검토함`, `재검토 필요`)와 해소 상태(`열림`, `보류`, `해소`)는 따로 움직입니다.
검토함이면서 보류인 기록은 정상적인 상태입니다. 초록색으로 다 바꾸는 것이 목표가 아닙니다.

## 5. 숫자를 읽는 법

- [관측] 녹차 사진 기록 3,872쌍 가운데 pH가 14를 넘는 기록은 **사진 기록 33개** 입니다.
- 같은 측정 시각과 다섯 값으로 묶으면 **후보 묶음 24개** 입니다.
- 이것은 식물 문제 33건이나 센서 고장 24회가 아닙니다. 같은 환경 측정이 여러 사진에 붙어 있을 뿐입니다.
- [관측] 148개 기록은 환경 시각이 사진보다 1~10초 늦습니다. 시간대가 확인되지 않아 `기록된 시각 차이·시간대 미확인` 으로 보여 주며 오류로 다루지 않습니다.

## 6. 작물·주차 모델 버튼

- 실제 데이터 모드에서만 기존 작물·주차 API에 사진 원본 바이트 한 장을 보냅니다. 파일 이름, 라벨, 캡션은 보내지 않습니다.
- 모델 결과는 다시 볼 이유일 뿐입니다. 신뢰도는 모델이 낸 숫자이고, 맞을 확률로 보정된 값이 아닙니다.
- 요청 뒤에 기록이 바뀌었으면 결과는 `오래됨` 으로 남고 채택되지 않습니다.
- 모델이 실패하거나 느려도 수동 검토, 보류, 수정, 인수인계는 그대로 됩니다.
- [주입] 공개 시연의 모델 불일치와 모델 실패 장면은 합성 장면이며 실제 추론이 아닙니다.

## 7. 인수인계 스냅샷

- 만들 때의 작업공간 버전을 서버가 다시 확인합니다. 그 사이 누가 바꿨으면 409 충돌이 나고 아무것도 저장되지 않습니다. 새로 고친 뒤 다시 만드세요.
- 스냅샷은 바이트와 SHA-256이 고정됩니다. 나중에 기록이 바뀌어도 예전 파일은 똑같이 내려받아집니다.
- 미검토 기록에는 규칙이 만든 `제안 다음 조치` 가 붙습니다. 사람의 승인처럼 보이게 꾸미지 않습니다.
- CSV를 엑셀로 열어도 수식으로 실행되지 않도록 `=`, `+`, `-`, `@` 로 시작하는 칸은 무력화됩니다.

## 8. AgentStream

[계획] 오늘은 `disabled_by_owner` 상태이며 질의는 503을 돌려줍니다. 실연동은 내일 예정입니다.
지금 되는 것은 읽기 전용 버전 문맥 내보내기와 수동 필터입니다. 에이전트 답변 예시나 성능 주장은 없습니다.

## 9. 개인정보와 공개 범위

- 공개 서버는 합성 기록과 직접 만든 SVG 사진만 씁니다. 화면 위쪽에 `합성 시연 데이터` 가 늘 보입니다.
- 클라이언트가 실제 데이터 모드를 켜거나 API 주소를 바꿀 수 없습니다.
- 원천 ZIP, 실제 사진, 비공개 모델 응답 보고서, DB, 키는 공개 저장소에 올리지 않습니다.

## 10. 자주 막히는 곳

| 증상 | 이유와 할 일 |
| --- | --- |
| 해소 버튼이 안 눌림 | 최신 재검사가 없거나 근거 메모/참조가 비었습니다 |
| 보류 저장 실패 | 이유와 다음 조치 두 칸이 모두 필요합니다 |
| 409 충돌 | 다른 창에서 먼저 바꿨습니다. 새로 고친 뒤 다시 하세요 |
| 사진이 안 보임 | 공개 모드에서는 실제 사진을 제공하지 않습니다 |
| 모델 결과가 `오래됨` | 요청 뒤 기록이 바뀌었습니다. 필요하면 다시 요청하세요 |

## 11. 아직 끝나지 않은 일

[계획] 공개 배포 주소와 GitHub 저장소 주소는 아직 확정되지 않았습니다. 확정되면 이 칸에 적습니다.
[계획] 검토 10회(R01~R10)와 실행 검증 10회(V01~V10)는 진행 중이며 통과로 표시하지 않습니다.
