## 1. 핵심 요약

**팜체크의 주 사용자를 농업 AI 개발자·데이터 담당자로 좁히고,
학습 전 데이터 검수와 재현 가능한 평가 자료 준비를 중심으로 발전시키는 방향입니다.**
현재 공개 화면은 녹차 기록 검토·인수인계 기능이며, 개발자용 화면 개편은 아직 하지 않았습니다.

- 초기 구현에서는 학습하지 않았지만, 후속 작업에서 기존 녹차 모델의 분류층을 실제 미세조정했습니다.
- 기록 조회, 규칙 검사, 사람의 검토·보류·보정, 고정 인수인계 기능을 구현했습니다.
- 기존 작물·주차 모델 API의 추론 연결은 시험했습니다. 모델 학습과는 별개입니다.
- 공개 시연은 합성 기록 8개와 직접 만든 SVG 이미지를 사용합니다.
- AIStream 12팀의 별도 실험 모델·서빙을 확인했고 실제 사진으로 HTTP 200 응답을 받았습니다. 공개 앱의 기본 모델 주소는 바꾸지 않았습니다.
- 공개 앱의 대화형 AgentStream 질의 기능은 이 모델 배포와 별개이며 미연동 상태입니다.

## 2. 데이터는 어디에 사용했나?

| 구분 | 사용 내용 | 모델 학습 여부 |
| --- | --- | --- |
| 원본 데이터 확인 | 녹차 사진과 JSON 기록의 대응, 값·단위·시각·출처 확인 | 학습 아님 |
| 규칙 검사 | 누락 값, 해석하기 어려운 숫자, 확인 기준에 해당하는 기록 선별 | 학습 아님 |
| 기존 모델 추론 | 사진을 기존 작물·주차 모델 API에 보내 결과를 받아 연결 확인 | 학습 아님 |
| 후속 전이학습 | 기존 녹차 가중치를 재사용하고 학습 자료 1,971장으로 분류층 갱신 | 실제 학습 수행 |
| 사람의 검토 | 검토 메모, 보류 이유, 다음 조치, 보정값과 판단 근거 저장 | 학습 아님 |
| 인수인계 | 선택한 범위와 미해결 질문을 저장 시점의 고정본으로 내보내기 | 학습 아님 |
| 합성 시연 데이터 | 화면과 처리 흐름, 충돌·오류 상황 시험 | 학습 아님 |

학습은 데이터로 모델의 가중치를 새로 만들거나 갱신하는 작업입니다.
추론은 이미 만들어진 모델에 입력을 보내 결과를 받는 작업입니다.
**팜체크에서 검토하거나 보정한 기록이 모델 재학습으로 이어지는 기능은 없습니다.**

### 실제 데이터 확인 범위

로컬에서 녹차 사진·JSON 기록 3,872쌍을 확인했습니다.
시연용 원문 확인 기준인 `pH > 14`에 해당하는 사진 기록은 33개,
원본 측정값 등을 기준으로 묶은 후보는 24개였습니다.

이는 식물 문제 33건이나 센서 고장 24회를 뜻하지 않습니다.
`pH > 14` 역시 녹차의 적정 생육 범위를 판정하는 기준이 아니라
원문을 다시 살펴보기 위한 시연용 선별 규칙입니다.

## 3. 기존 AI 모델은 어디까지 사용했나?

기존 작물·주차 모델에 실제 사진 5장을 보내 HTTP 200 응답과 결과 파싱을
확인했고, 추가 1건은 로컬 앱의 모델 요청부터 검토 흐름까지 연결해 확인했습니다.

- 전송 대상은 사진 원본 바이트입니다.
- 원본 파일명은 임의 식별자로 바꾸고, JSON·작물/주차 정답 라벨·캡션·원본 경로는 보내지 않습니다.
- 모델 출력은 사람이 다시 확인할 참고 정보이며 정답이나 진단 결과로 취급하지 않습니다.
- 모델 요청만으로 기록을 검토 완료 또는 해소 상태로 만들지 않습니다.
- 이 시험은 연결 확인입니다. 모델 정확도나 현장 효과를 측정한 실험은 아닙니다.

**우리 쪽 학습 여부와 외부 제공자의 요청 데이터 재사용 여부는 별개입니다.**
외부 제공자의 데이터 보관·재사용·학습 정책은 이 구현 검증에서 확인하지 않았습니다.

### 후속 전이학습 결과

팀 B200 GPU에서 특징 추출·6개 epoch·고정 시험 평가·가중치 저장까지 21초에 완료했습니다.
사진 1,033장의 제공 라벨 기준 일치 건수는 기존 1,024장, 추가 학습 후 1,025장입니다.
개선은 한 장이며, 남은 불일치 8장은 사람의 검수 후보로 보관했습니다.

기존 모델의 사전학습 자료 중복 가능성과 식물 고유 ID 부재 때문에 독립적인 정확도로
주장하지 않습니다. 라벨을 수정하지 않은 실험이므로 데이터 검수 효과를 입증한 것도 아닙니다.
상세 지표·주차별 한계는 `docs/growth-week-pilot.md`에 있습니다.

## 4. 현재 사용 가능한 흐름

```text
확인 후보 선택
  → 원문·사진·적용값·단위·출처 확인
  → 검토 메모 또는 보류 이유·다음 조치 기록
  → 필요한 경우 보정값 저장
  → 현재 값으로 재검사
  → 사람이 관련 근거를 선택해 해소 판단
  → 범위를 확인하고 인수인계 고정본 생성
```

여기서 **검토함과 해소는 다른 상태**입니다.
봤다고 표시한 기록도 미해결이거나 보류 상태일 수 있습니다.
재검사를 실행했다고 자동으로 해소되지도 않습니다.

원문은 수정하지 않고 보정값을 별도로 저장합니다.
보정 후에는 이전 검토·해소 판단을 그대로 인정하지 않고 다시 확인하게 합니다.
인수인계 고정본은 이후 기록이 바뀌어도 저장 당시 내용으로 유지됩니다.

## 5. UX/UI 개선과 검증 결과

### 반영한 개선

- 긴 식별자는 짧게 표시하되 펼치면 전체 값을 확인할 수 있도록 정리
- 원문·해석값·적용값·단위 출처를 구분해 표시
- 검토 / 보류 / 보정 / 재검사 / 해소를 행동별 탭으로 분리
- 기록별 작성 초안 보존과 필수 입력의 인라인 오류 안내
- 저장 중 중복 요청 방지, 충돌 및 응답 끊김 복구
- 인수인계 범위·저장 결과·JSON/CSV/HTML 다운로드 용도 안내
- 모바일에서 긴 ID와 선택 문구 때문에 화면이 과도하게 늘어나던 문제 개선

### 확인한 결과

- 기존 테스트 66개와 타입·린트·JavaScript 구문 검사 통과
- PC 1440px, 모바일 390px·320px 화면 검증
- 실제 두 탭 충돌, 지연 응답, 빈 입력, 연결 실패 후 재시도 검증
- 공개 서비스에서 보류 → 보정 → 재검사 → 근거 해소 → 인수인계 실행 확인
- 배포 및 후속 기록 수정 뒤에도 이전 고정본 내용이 동일함을 확인
- 최종 독립 리뷰 승인 후 공개 서버와 GitHub에 반영

이 결과는 구현 동작과 화면 검증에 관한 것입니다.
현장 사용자 인터뷰, 작업 시간 절감, 농장 생산성 향상은 아직 측정하지 않았습니다.

## 6. 공유·시연 시 알아둘 점

- 공개 서버에는 실제 원천 ZIP이나 사진을 올리지 않았습니다.
- 공개 모델 불일치·실패 사례는 합성 시연이며 실제 추론 결과처럼 설명하지 않습니다.
- 초안은 현재 탭에서 기록을 이동해도 유지되지만, 새로고침이나 탭 종료 후에는 복원되지 않습니다.
- 익명 작업공간은 브라우저 쿠키로 구분됩니다. 다른 팀원의 브라우저와 같은 작업공간을 공유하는 협업 계정 기능은 아닙니다.
- 팀에 결과를 전달할 때는 필요한 인수인계 파일을 내려받아 공유합니다.
